# 连接模型

[English](/setup) · [安装与快速开始](/zh/)

桌面版已经把常用的连接方式收进**连接模型**界面。一般使用不需要填写 endpoint，也不需要修改 `.env`：选择入口、完成授权或填入 key，再选择模型即可。

## 在 App 中完成连接

1. 点击工具栏中的**连接模型**；
2. 选择服务商、Coding Plan、Ollama 或自定义连接；
3. 按界面提示授权，或粘贴对应服务提供的 key；
4. 点击**获取模型**，勾选要显示的模型并保存。

ThoughtDAG 会处理预设 endpoint、读取可用模型、保留你的选择，并在工具栏中提供默认模型。以后点击连接旁的编辑按钮，可以刷新目录或调整已启用的模型。

## 选择哪种入口

| 你的情况 | 在 App 中选择 | 还需要准备什么 |
|---|---|---|
| 希望快速开始 | **OpenRouter** | 在浏览器完成授权，回到 App 选择模型 |
| 已有服务商 API key | 对应服务商预设 | 粘贴 key；endpoint 已经预填 |
| 已有 Coding Plan | 对应的 Coding 预设 | 使用该计划提供的 key |
| 使用本地模型 | **Ollama** | 先让 Ollama 在本机运行；App 会读取模型目录 |
| 使用其他兼容服务 | **自定义 endpoint** | Base URL，以及该服务要求的凭证 |

当前界面包含 OpenRouter、智谱 GLM / Z.ai GLM、GLM Coding、Kimi Code、MiniMax、DeepSeek、OpenAI、Google AI Studio、Kimi / Moonshot、Ollama 和自定义 OpenAI-compatible endpoint 等预设。界面实际显示的模型取决于对应服务当前返回的目录和你的账户权限。

## 订阅与 Coding Plan

如果某项计划提供可用于兼容接口的 key，直接选择对应预设并粘贴 key，不需要自行填写专用 endpoint。GLM Coding、Kimi Code 和 MiniMax 等入口已经包含在 App 中。

普通消费者订阅不一定同时提供第三方 API 访问。App 中的 **ChatGPT 订阅**属于可选的本地兼容入口：ThoughtDAG 可以连接已经在本机运行的适配服务，但当前版本不会替你安装或启动该服务。没有这项本地环境时，使用 OpenRouter、服务商 API key 或本地 Ollama 更直接。

## Ollama 本地模型

先启动 Ollama，再在**连接模型**中选择 **Ollama → 获取模型**。默认本地地址已经预设，不需要填写 key。若你使用的是其他本地运行环境，可通过**自定义 endpoint**加入。

本地模型请求留在所选本地 endpoint；启用网页搜索、学术搜索或其他远程工具时，相应查询仍会发送给所启用的服务。

## 模型、视觉与工具

- 工具栏中的模型是新节点的默认模型；
- 每个节点可以单独指定模型，每个回答版本会记录实际使用的模型；
- 图片内容需要视觉模型，或先保存为可供文本模型使用的伴随文字；
- 网页搜索、学术搜索与 MCP 工具是独立能力，不会因为切换模型而自动改变图中的上下文路径。

继续阅读：[模型、工具与记忆](/zh/guides/models-tools) · [隐私与存储](/zh/reference/privacy-storage)

## 连接机制（开发者）

应用内连接不是另一套模型协议，而是把兼容 endpoint 转成 ThoughtDAG 的运行时模型目录：

```text
服务商预设 / 自定义 endpoint
        ↓ 获取模型
兼容接口的 /models 目录
        ↓ 用户选择并保存
浏览器中的连接信息与模型选择
        ↓ 发起生成
运行时模型注册表 → 所选 endpoint
```

### 预设与模型发现

预设主要保存稳定的 Base URL、取 key 的入口和少量推荐项，不把完整型号表写死在文档或界面里。点击**获取模型**时，本地或桌面代理会请求 endpoint 的 `/models`；只有未提供该接口的连接才使用预设目录。刷新连接会重新读取目录，同时保留仍然有效的用户选择。

### 运行时注册与请求路径

用户确认的连接和模型选择保存在当前浏览器配置中。生成时，ThoughtDAG 根据节点记录的模型 ID 找到对应连接：

- 桌面版和本地运行通常经过随应用运行的本地代理，再访问所选 endpoint；
- 托管版中，少数经过兼容性验证的连接可以由浏览器直达，其余能力取决于部署环境；
- 运行时连接按请求建立模型映射，不会改写 `.env` 中的 server 配置；
- key 不写入普通画布备份。具体边界见[隐私与存储](/zh/reference/privacy-storage)。

### `.env` 与自定义扩展

从源码运行时仍可完全通过界面连接模型。只有希望 server 在启动时统一注册服务商时，才需要把 `.env.example` 复制为 `.env`。界面连接会在这套启动目录之上加入当前用户选择；模型 ID 冲突时，以 server 已注册项为准。

自定义服务需要提供兼容的模型和生成接口。模型目录、能力、速率限制、费用与数据处理方式由所连接的服务决定。额外的 MCP server 则在 `mcp.config.json` 中配置。

## 连接本地 Agent 会话

模型连接决定“由哪个 endpoint 生成回答”；Agent 对话地图负责把本地 Agent 会话读入可整理的镜像画布。桌面版可在 **Agent 对话地图 → 接入** 中重新检测目录，并通过**启用/更新**安装一键打开命令。
